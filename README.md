# 🏟️ הזירה – סימולטור מונטה קרלו

סימולטור אינטראקטיבי לשעשועון **"הזירה"** (כאן 11). הוא מריץ מאות אלפי משחקים כדי לענות על שאלות כמו:
**כמה כסף צפוי להרוויח כל מתמודד? מה הסיכוי שלו לזכות בפרס הגדול? איך משפיעים עליו המיקום על הלוח, היכולת שלו והאגרסיביות?**

הממשק בעברית ורץ בדפדפן. את מנוע הסימולציה כתבתי ב-Python ו-[Numba](https://numba.pydata.org/), ועל לוח 8×8 הוא מריץ יותר מ-150,000 משחקים בשנייה.

---

## 📜 חוקי המשחק

- **הלוח:** כל מתמודד מתחיל במשבצת משלו על לוח דו-ממדי. ברירת המחדל היא 8×8 עם 64 מתמודדים.
- **תור:** הזירה מגרילה **תוקף**. התוקף מגריל **יריב** באופן אחיד מבין כל השכנים שלו, כלומר כל המתמודדים שגובלים בשטח שלו.
- **דו-קרב:** התוקף מנצח בהסתברות $f(p_{\text{תוקף}}, p_{\text{מגן}})$. **המפסיד מודח**, והמנצח לוקח את כל המשבצות שלו.
- **אחרי ניצחון:** מנצח הדו-קרב, בין אם היה התוקף ובין אם המגן, ממשיך לתקוף בהסתברות $a$ שלו. בהסתברות המשלימה הוא חוזר לזירה, והזירה מגרילה תוקף חדש.
- **פרס קטן:** אחרי כל $x-1$ הדחות, שני המתמודדים עם הכי הרבה משבצות נלחמים על הפרס הקטן. אף אחד לא מודח בקרב הזה, ורצף התקפות שהיה באמצע ממשיך אחריו. שוויון במספר המשבצות נשבר באקראי.
- **גמר:** כשנשארים שני מתמודדים, הם נלחמים על **הפרס הגדול**. אם הגמר והפרס הקטן חלים באותו קרב, מתקיים רק הגמר.
- מתמודד שהודח **שומר** את הפרסים שכבר זכה בהם.

### פרמטרים

| פרמטר | ברירת מחדל | תיאור |
|---|---|---|
| גודל הלוח | 8×8 | עד 40×40. בוחרים אילו משבצות פעילות |
| שכנות | ישר בלבד | ישר בלבד (4 שכנים) או ישר + אלכסון (8 שכנים) |
| בחירת תוקף | מכל המתמודדים | מכולם, או רק מבעלי משבצת אחת (אם אין כאלה, מכולם) |
| תדירות פרס קטן $x$ | 8 | קרב על הפרס הקטן אחרי כל $x-1$ הדחות. אפשר גם לכבות |
| פרס קטן / גדול | ‎₪10,000 / ‎₪200,000 | |
| יכולת $p$ | 0.5 | לכל מתמודד בנפרד, בטווח $[0,1]$ |
| אגרסיביות $a$ | 0.5 | לכל מתמודד בנפרד: ההסתברות להמשיך לתקוף אחרי ניצחון |
| מספר סימולציות | 100,000 | |

> **דרישת קישוריות:** המפה חייבת להיות רכיב קשיר אחד. אחרת יש קבוצות מתמודדים שלעולם לא ייפגשו, ואי אפשר להגיע לגמר. הממשק מסמן משבצות בלי שכן ואיים מנותקים, ויש כפתור שמשאיר רק את האי הגדול.

## ⚔️ מודלי הדו-קרב

$f(p_1,p_2)$ היא ההסתברות שהתוקף (יכולת $p_1$) מנצח את המגן (יכולת $p_2$). כל המודלים מקיימים
$0 \le f \le 1$, $f(p,p)=\tfrac12$ ו-$f(p_1,p_2)+f(p_2,p_1)=1$. לכל מודל יש פרמטר חדות. בנוסחאות $d = p_1-p_2$.

| מודל | נוסחה | פרמטר |
|---|---|---|
| חזקה (Tullock / Bradley–Terry) | $\dfrac{p_1^{z}}{p_1^{z}+p_2^{z}}$ | $z$ |
| יחס סיכויים (Log5) | $\dfrac{[p_1(1-p_2)]^{z}}{[p_1(1-p_2)]^{z}+[p_2(1-p_1)]^{z}}$ | $z$ |
| לוגיסטי (Elo) | $\dfrac{1}{1+e^{-k d}}$ | $k$ |
| פרוביט (Thurstone) | $\Phi(k d)$ | $k$ |
| ארקטנגנס (Cauchy) | $\tfrac12+\tfrac1\pi\arctan(k d)$ | $k$ |
| לינארי חסום | $\min\big(1,\max(0,\tfrac12+\tfrac k2 d)\big)$ | $k$ |
| הפרש בחזקה | $\tfrac12+\tfrac12\,\mathrm{sgn}(d)\,\lvert d\rvert^{z}$ | $z$ |
| רעש אחיד (משולשי) | CDF של התפלגות משולשית ב-$\frac{d}{2w}$ | $w$ |

בנוסף יש **מקדם מזל** $\lambda$ שאפשר להפעיל מעל כל מודל: $f_{\text{final}}=(1-\lambda)f+\tfrac{\lambda}{2}$. בהסתברות $\lambda$ הקרב הוא הטלת מטבע הוגנת.

## 🚀 התקנה והרצה

נדרש Python 3.11 ומעלה.

```bash
git clone https://github.com/tamirgabgab/The-arena.git
cd The-arena
python -m venv .venv
```

**Windows:**
```bash
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python run.py
```

**macOS / Linux:**
```bash
.venv/bin/pip install -r requirements.txt
.venv/bin/python run.py
```

הדפדפן ייפתח אוטומטית בכתובת **http://127.0.0.1:8000**. בהפעלה הראשונה Numba מקמפל את המנוע, וזה לוקח כ-10 שניות. בהפעלות הבאות המנוע נטען מהמטמון.

אפשרויות: `python run.py --port 8080 --no-browser`

### בדיקות

```bash
python -m pytest
```

הבדיקות מכסות:
- תכונות כל המודלים.
- ולידציה של הלוח.
- שמורות של המשחק: זוכה גדול אחד בכל משחק, ומספר הפרסים הקטנים המדויק.
- השוואה לתוצאה אנליטית בשני שחקנים.
- סימטריה.
- דטרמיניזם עם אותו seed, ללא תלות במספר ה-threads.
- ה-API.

## ⚙️ איך המנוע עובד

[`arena/engine/simulate.py`](arena/engine/simulate.py) בנוי כך שכל משחק ירוץ מהר ככל האפשר:

- **מטריצת הסתברויות מחושבת מראש:** $W_{ij}=f(p_i,p_j)$ מחושבת פעם אחת לכל הרצה, ולכן בתוך המשחק אין אף קריאה לפונקציית המודל.
- **שכנות כ-bitset:** לכל מתמודד שורת ביטים של היריבים הנוכחיים שלו. כשמנצח בולע מפסיד, עושים OR בין השורות ומפנים את שכני המפסיד אל המנצח. העלות היא $O(N/64+\deg)$, בלי לסרוק משבצות, גם כשלמנצח יש מאות משבצות. בחירת יריב אקראי נעשית בעזרת popcount.
- **רשימות עם swap-remove:** רשימת המתמודדים החיים ורשימת בעלי משבצת אחת מאפשרות הגרלת תוקף ב-$O(1)$.
- **תוצאות בלי לשמור את הריצות:** הרווח של מתמודד הוא תמיד $k\cdot y + b\cdot B$, כאשר $k$ הוא מספר הפרסים הקטנים ו-$b\in\{0,1\}$. לכן נשמר רק מונה `counts[player, k, b]`. ההתפלגות המלאה מדויקת, והזיכרון זניח.
- **מקביליות ושחזוריות:** `prange` של Numba מחלק את העבודה על כל הליבות. לכל סימולציה מחולל אקראי משלה (xoshiro256\*\*) שנזרע מ-(seed, מספר הסימולציה), ולכן אותו seed נותן תוצאה זהה בדיוק.
- **התקדמות וביטול:** ההרצה מתבצעת בחלקים, והשרת שולח עדכון התקדמות דרך WebSocket אחרי כל חלק. ביטול מחזיר את התוצאות החלקיות.

### API

| נתיב | תיאור |
|---|---|
| `GET /api/models` | רשימת המודלים: שם, הסבר, LaTeX ופרמטר |
| `POST /api/validate` | בדיקת קישוריות של לוח |
| `WS /api/run` | הרצת סימולציה: שולחים הגדרות, מקבלים `progress` ובסוף `result`. אפשר לשלוח `cancel` |
| `GET / POST /api/runs` | רשימת הסימולציות השמורות / שמירת סימולציה |
| `GET / PATCH / DELETE /api/runs/{id}` | טעינה, שינוי שם ומחיקה |

הסימולציות השמורות נמצאות בתיקייה `saved_runs/`, והיא לא נכנסת ל-git.
